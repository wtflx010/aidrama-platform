# 四套并行视频子系统收敛设计方案

> 2026-09 · 针对「视频生成管线调研」第 5 项待办：收敛 4 套并行视频子系统。
> 目标：把分镜→提示词→帧数→资产参考→模型路由→时间轴 这套编排逻辑收拢到**一个共享管线层**，
> 让「单镜 / 幕级 / 画布导演台 / 项目连续长片」四条入口只做参数化分发，**不再各写一份**。

## 1. 现状：四套并行子系统与重复点

| 子系统 | 文件 | 行数 | 职责 | 入口 |
|---|---|---|---|---|
| 单镜 | app/services/video_service.py | 414 | 单个分镜：帧数估算、模型路由、对白剥离、首尾帧回填 | POST /videos + 面板单镜重跑 |
| 幕级 | app/services/episode_video_service.py | 971 | 整幕逐镜批量生成（并发/进度/分镜粒度），含分段/对齐 | POST 幕级视频 |
| 画布导演台 | app/services/canvas_director_service.py | 257 | 多镜连续长片（AIMixer 时间轴、公共参考、段间引导） | POST /canvas director/scheme |
| 项目连续长片 | app/services/project_longvideo_service.py | 232 | 一集一条连续整片（复用画布导演台时间轴/参考/模型） | POST /episodes continuous-film |

### 1.1 已确认的重复点（grep 实测）

| 逻辑 | 出现于 | 现状 |
|---|---|---|
| 帧数/时长换算 | video_service · episode_video_service · canvas_director_service | 单镜 8n+1 估算 + provider 再对齐；导演台直接 17n+5（已通过 constants.snap_h3_frames 部分统一，但 episode 仍各写） |
| 视频模型路由 | video_service · canvas_director_service · project_longvideo_service | 各自 _resolve_*_model，均按 capability.video_kind=minimax/minimax_ref |
| 资产/参考图收集 | episode_video_service · canvas_director_service · project_longvideo_service | 各自收集 + 去重 + 上限 9；`resolve_shot_asset_refs` 定义在 tasks.generate_video |
| 对白剥离/口播注入 | video_service · episode_video_service · project_longvideo_service | 各自 strip_dialogue / 正对镜头口播 / 画外音 / 内心独白 / 语速提示 |
| 分辨率档位 | 各处 dims_for_ratio / _resolve_dims | episode 已 import video_service.dims_for_ratio（部分复用） |
| 导演时间轴 | canvas_director_service · project_longvideo_service | project_longvideo 已 import canvas_director（已复用 build_director_timeline 等） |

> 结论：真正重复的是「帧数/模型/参考/对白/时间轴」这 5 类编排原语；而「谁触发、按什么粒度、回写到哪里」各入口差异大。
> 所以**收口点应是「编排原语层」，而非把 4 个入口变成一个**。

## 2. 目标架构

新增共享包 `backend/app/services/video_pipeline/`（纯能力，无 DB 会话编排责任），四入口只负责「取分镜 → 调 orchestrator → 建任务回写」。

```
backend/app/services/video_pipeline/
  frames.py        # 时长→帧数（唯一权威；单镜估算 & H3 网格 & 上限）。替代 video_service/episode/canvas 的各自换算
  model.py         # 视频模型路由（minimax / minimax_ref / director）。替代 3 处 _resolve_*_model
  refs.py          # 资产/参考图收集、去重、9 图上限、跨镜去重。替代 episode/canvas/longfilm 的各自 _collect_global_refs / resolve_shot_asset_refs
  prompts.py       # 单镜提示词编排：对白剥离、口播/画外音/内心独白、语速/口型指令、P5 点位运镜、增强稿解析。替代视频_service/episode/longfilm 的各自注入
  timing.py        # 幕级分段时间轴/切点估算（连续片切点、幕级片段偏移）。替代 episode_video_service 的分段对齐
  orchestrator.py  # 统一入口 build_spec(db, segments, *, mode, config) -> VideoSpec
```

VideoSpec（纯数据，可 JSON 化）字段：
```
{  prompts: [{segment_id, prompt, duration_sec, from_prev}],   // 每镜增强稿/编排稿
   refs: {global: [{index,imageFile,label}], per_segment: {sid:[...]}},
   frames: {per_segment: {sid: n}, 或 timeline_segments:[{start,length,prompt}] },
   model: {id, kind},  fps, ratio, res, width, height, ref_max_size,
   mode: "single"|"episode"|"director"|"continuous",
   timeline: {...}?  // director/continuous 才生成
}
```

四入口改造（薄壳）：
```
video_service.generate          -> build_spec(mode="single")   -> 逐镜单任务（沿用现有派发）
episode_video_service.generate  -> build_spec(mode="episode")  -> 逐镜批量 + 进度（保留该文件批量编排，仅内部改用共享原语）
canvas_director_service.generate -> build_spec(mode="director") -> 时间轴/整片（保留现有 timeline 组装，改为调用共享）
project_longvideo_service.generate -> build_spec(mode="continuous") -> 复用 director 时间轴（已共享）
```

## 3. 收敛步骤（分阶段，先「只搬不改」再「行为对齐」）

> 宗旨：**第一步绝不改出片行为**，只把重复代码搬进共享包并让 4 个入口改 import；再逐步统一参数与网格。每步可独立回归。

### S1 帧数与时长原语（改动最小、已验证部分）
- 已建 `constants.py`：snap_h3_frames / CHARS_PER_SEC / H3_FRAMES_MAX / H3_DURATION_MAX_SEC。
- 待办：让 `episode_video_service` 与 `canvas_director_service` 也改为统一调用（canvas 已复用）；抽 `duration_to_frames`。
- 验收：`test_h3_grid_and_constants.py` + estimate/导演台一致性全过；不改出片。

### S2 模型路由原语
- 新建 `video_pipeline/model.py`：`resolve_video_model(db, model_id=None, *, kind)` 统一 minimax/minimax_ref/director 判定。
- 替换 video_service `_resolve_shot_video_model`、canvas `_resolve_director_model`、project_longvideo 的模型获取。
- 验收：三条入口对同一模型集返回一致；保留「显式 model_id 优先」语义。

### S3 资产/参考原语
- 把 `resolve_shot_asset_refs`（现 tasks.generate_video）与画布/longfilm 的 `_collect_global_refs` 收进 `video_pipeline/refs.py`。
- 统一：跨镜去重、9 图上限、按机位裁格子（参考踩坑58）、`enable_common_refs` 开关语义。
- 验收：单镜/幕级/画布/长片对同一分镜集产出相同 refs（单测比对）。

### S4 提示词原语
- 收 `strip_dialogue_lines`、正对镜头口播、画外音/内心独白、`_PACING_HINT`、P5 运镜/点位、增强稿解析 进 `video_pipeline/prompts.py`。
- 统一语速常数（已 5.5）；对白/旁白规则单点维护。
- 验收：`test_project_longvideo_speech`、`test_video_frames`、`test_prev_tail_*` 全过；逐入口 diff 一致。

### S5 幕级/连续片时间轴与切点
- 收 `episode_video_service` 的分段对齐/切点估算 与 `_crop_film_to_segments` 进 `timing.py`；`project_director_generate` 复用。
- 验收：幕级导出时间轴、连续片切点裁分镜与现有产物一致（用现有测试 + 冒烟）。

### S6 编排出口 + 清理
- orchestrator 收口：按 mode 组装 VideoSpec；四个入口只做「取分镜→调 orchestrator→派发/回写」。
- 删除各入口内重复的私有函数；保留 `episode_video_service` 的批量并发/进度逻辑（那是入口编排，不属于共享原语）。
- 验收：全量单测 + 前端 tsc + 后端 import 冒烟 + 一条真实 mock/真实出片链路跑通。

## 4. 行为对齐决策（S6 收敛时）

| 项 | 现状 | 收敛后（推荐） |
|---|---|---|
| 帧数网格 | 单镜 8n+1 估算→provider 再对齐；导演台 17n+5 | 统一 H3 17n+5（H3 是唯一生视频模型）；estimate 保留但明确为「估算，成片前落 H3 网格」 |
| 语速常数 | 曾有 4 / 5.0 / 5.5 | 唯一 CHARS_PER_SEC=5.5 |
| 模型来源 | 各 _resolve | 唯一 resolve_video_model（minimax/minimax_ref/director） |
| 参考上限 | 9 图 | 统一 9 图，多视图按机位裁格 |
| 对白/旁白 | 各入口注入 | 统一 prompts 编排（正对镜头=口播，远景/背影=画外音，duration 超容=提速提示+只念引号内） |

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 行为回归（改 import 引入差异） | 第一步严格「只搬不改」；逐步用快照/单测对比 |
| episode_video_service(971 行) 耦合深 | 只收敛「原语」，保留其批量编排；不一次重写 |
| 参考图裁剪引入新差异 | 复刻踩坑58「按机位裁格」，先做 refs 纯函数单测 |
| 视觉/LLM 评分、抽帧等新链路 | 与本次并行，互不阻塞（evaluate 已独立接入） |
| 破坏运行中系统 | 每步跑全量单测 + import 冒烟 + 前端 tsc，逐阶段合并 |

## 6. 里程碑

| 阶段 | 内容 | 验收 |

## 7. 建议优先级
1. **S1–S3**（帧数/模型/参考）改动小、收益大、风险低——先做。
2. **S4**（提示词）涉及对白/旁白，需逐入口 diff，谨慎。
3. **S5–S6**（时间轴/编排出口）为结构性收口，建议独立排期 1 个迭代并配回归。
