# AI漫剧 后端「视频生成管线」调研报告（只读，未改任何文件）

## 结论速览
后端视频管线整体成熟度较高：单镜/关键帧/幕级链路有较健全的错误处理、预校验、重置语义、孤儿恢复；但导演台/连续长片两条新链路仍是「依赖 166 的 mock/半成品」，且存在多条并行重复的视频子系统、若干未接线/半成品功能与测试覆盖缺口。

## ③ 视频生成链路质量短板

### A. 链路分裂：4 套并行视频子系统，职责重叠、prompt 逻辑重复
- 逐镜：video_service.generate + tasks/generate_video.py。
- 幕级：services/episode_video_service.py（971 行，plan_groups/build_segment_prompt/build_speech_block/build_sfx_block/plan_design_images）重新实现分幕、去重、提示词拼装，与逐镜链路的 prompt_enhance_service/compose_segment_prompt 大量重复。
- 画布导演台：canvas_director_service.build_director_timeline（时间轴 JSON）。
- 连续长片：project_longvideo_service.generate 直接 import 复用 canvas_director_service 的 _collect_global_refs/_resolve_dims/_resolve_director_model/build_director_timeline，但又各自重写 _segment_duration_sec/MAX_DIRECTOR_DURATION_SEC/_prompt_with_speech。
  → 同一段「分镜→视频」逻辑有多份实现，修一处易漏另外几处。

### B. 帧数/时长口径不一致
- video_service.py:18-88 _FRAME_OPTIONS=(121…361)，但 frames_for_duration 上限设到 441，注释口吻与列表不同步；estimate_num_frames 以 segment.duration×fps 取最近 8n+1。
- canvas_director_service._snap_h3_frames（19-24）用 H3 17n+5 网格，默认 124；与单镜链路 8n+1 是两套帧数体系，同段时长两条链路出不同帧数。
- 语速常数不一致：project_longvideo_service._prompt_with_speech 按 5 字/秒估算容量（75 行），video_service._CHARS_PER_SEC=5.5，两个常数（5.0 vs 5.5）不同。

### C. 首尾帧衔接/接缝
- video_service._resolve_next_keyframe_url（121-142）本镜尾帧=下一镜最新成功关键帧，仅当下一镜已生成关键帧才回填，否则 None 回退 → 跨镜画面接缝在无关键帧时断裂。
- generate_video.py 的 prev_tail 硬首帧链路（366-412）较完整（切 I2V、强制 32 倍数、先 resize、抽取上一镜真实末帧 358-361），但仅覆盖「上一镜视频已生成」情形；上一镜未完成时衔接仍退化。

### D. 音频对齐/字幕时间轴
- generate_export.py:745-798 _resolve_segment_voicelines 字幕时间轴按 VoiceLine 时长顺序累加（第 i 条 start=前面之和），假定对白紧挨，未按各条实际起始偏移对齐，多对白有间隔会被压平；且语音时长与画面镜头时长无交叉校验。
- compose_segment_multi（216-267）多对白拼接后 target=max(v_dur, voice_total)，视频短则以 tpad clone 末帧补齐 → 长对白会产「末帧静止重复」画面。
- generate_export.py:460-508 mix_bgm_sfx BGM 用 aloop=loop=-1:size=2e9 近似无限循环并用 -shortest/afade 限制；BGM 循环长度依赖 duration_ms，若该字段缺失（dur_ms=0）则完全不循环，BGM 可能提前结束。
- 重复 bug：generate_export.py:1207-1208 连续两行 shutil.rmtree(tmpdir, ignore_errors=True)（export_episode 的 finally）冗余重复。

### E. 分辨率档位
- video_service._RESOLUTION_DIMS（33-59）720p=1280×720 非 32 倍数，注释自认「provider 会回退最近可生成档」；H3 需 32 倍数 patchify，720p 生成时实际被回退，与用户所选的 720p 不符（仅超分才触及 1080p）。
- generate_video.py:390-408 prev_tail 场景 _grade.get(_ratio, _grade["9:16"]) 比例判定用宽高比近似（±0.06 容差），可能轻微偏移尺寸。

## ④ 代码健壮性/可靠性短板

- canvas_director_service.py:53-57 用字符串 Model.model_type=="video"/provider_type=="comfyui" 过滤，而同项目 video_service/keyframe_service 用枚举 ModelType.video → 列表/枚举两套写法混用，模型路由口径不一致。
- evaluate_service.py:146-168 llm_score 用 _extract_json（find { … }）+float(data.get(k,5))；若 LLM 返回非数值/缺字段抛异常，外层 catch 后静默回退规则分（171-191）→ 用户感知「评估不准」。
- evaluate_service.py:56-104 rule_scores 是硬编码启发式（首镜无对白-3、远景-2、情绪词±2、末镜留钩±1），非真实模型。
- generate_video.py:856-865 异常后派发 recover_orphan_video.delay 时用裸 try/except，失败仅打日志 → 恢复任务派发本身失败则静默丢失。
- canvas_director_generate.py:26,55 mock 生成用 pass/占位文件，mock/real 分支只在任务内 if 判断（161），两分支产物语义差异无对外校验 → 前端无法区分真片 vs 占位假片。
- project_longvideo_service.py:36-37 _segment_duration_sec 与 canvas_director 完全同名重复实现；长片与画布两入口共用 166 同一提交协议，任一方改协议另一方需同步。
- dub_episode.py:108-116 全函数一个 except Exception + str(e)[:500] → 细分异常全部折叠成一整集失败，无逐条重试/局部成功。
- export_service.py:232-243 _result_file_size 仅对 succeeded 且 result_url 含 /exports/ 返回大小，否则 None；成片文件缺失静默返回 None → 前端拿不到「文件确实没有」与「未完成」的区别。
- batch_service.py:84-174 批量视频非链式时逐镜 video_service.generate 生成，父任务只存子任务 ID，若某子任务失败，编排任务无统一汇总/去重重试逻辑。

### 幂等/重试/超时/取消
- 超时：generate_video.py:807 用 settings.celery_video_timeout（config.py:29 默认 1800s）轮询；run_with_polling 超时后抛 ProviderError → 置 failed 并派发 recover_orphan_video。无「超时→自动重试 N 次」，ComfyUI 纯轮询，重试主要靠上层 recover。
- 取消：video_service/keyframe_service._cancel_related_task 会 sync_cancel_provider 同步取消 ComfyUI；但 canvas_director/project_director 的 Task 未见单独清理/取消失效挂起 166 任务的专用逻辑。
- 幂等：upscale_service.has_upscaled（73-83）以「状态非 failed」判重；但超分/幕级等长任务无「运行中允许多次触发」的幂等锁，用户连点可能重复建任务。
- generate_export.py 多处 subprocess.run(check=True, capture_output=True) 无显式 timeout，ffmpeg 挂起会卡死 Celery worker（仅外层捕 CalledProcessError，无超时保护）。
- prompt_enhance_service.py:1010-1086 六段式硬校验（缺 detailed_description/空槽占位/中文泄漏）与重试较完善，但每次重试 sleep 2s + 多次 provider.chat，是高耗时路径；_assets_fingerprint（1089-1119）只在有引用资产时算指纹，无资产时缓存键可能过宽。
